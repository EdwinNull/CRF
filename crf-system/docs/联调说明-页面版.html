启动服务

本机 conda 环境名 crf，命令用绝对路径或激活环境后直接调用。

# 后端（首次需先迁移，已做过可跳过）
cd crf-backend
/opt/anaconda3/envs/crf/bin/python -m alembic upgrade head
/opt/anaconda3/envs/crf/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# 前端（另一终端）
cd crf-system
npm run dev

打开 http://localhost:5173。可用以下命令体检：

curl http://localhost:8000/health        # → {"status":"ok"}
curl -o /dev/null -w "%{http_code}" http://localhost:5173/   # → 200

仍为前端本地（分层边界）

以下数据由前端 PatientContext + localStorage 管理，未落库到后端。

原因：后端将访视数据存为无结构的 JSON blob，与前端强类型富模型差异过大，强行落库会丢字段。界面显示与编辑均正常，仅刷新后不持久化到后端。
  • V1 详表 —— 人口学、病史、四诊、实验室等富字段
  • V2–V6 访视明细 —— VAS / 四分法 / RQLQ / 中医证候 / 药物评分等
  • 不良事件、合并用药、非药物疗法、完成情况

手动联调验证清单

  1. 用 doctor01 · Doctor@0101 登录（中心选 01）
    → 登录成功，进入患者列表
  2. 输错密码再登录
    → 提示 用户名、密码或研究中心不正确
  3. 新建患者：筛选号 001、缩写 e.g. AAAB、入组日期
    → 创建成功并跳转 V1；列表出现该患者（中心 01）
  4. 切 doctor02 登录看列表
    → 看不到 01001 号患者（中心隔离生效）
  5. 换 admin 进导出页，勾中心/状态/日期导出
    → Excel 正常下载
  6. 用 doctor02 进导出页
    → 提示 无导出权限（仅 center01 / admin）
  7. V1 页填写后提交（入选全「是」、排除全「否」）
    → 状态从「筛选中」变 治疗中，随机号自动生成

curl 直达后端

绕过前端直接验证接口（同样地址，本机直连 :8000 或经代理 :5173 均可）。

TOKEN=$(curl -s -X POST http://localhost:8000/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin@crf2026","center_id":"01"}' \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['access_token'])")

# 列患者
curl -s http://localhost:8000/api/v1/patients -H "Authorization: Bearer $TOKEN"

# 建患者
curl -s -X POST http://localhost:8000/api/v1/patients \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"screening_no":"01008","name_abbr":"BBBB","gender":"男","age":40,"height":170,"weight":65,"enrollment_date":"2026-08-11"}'

# 导出 Excel
curl -s -o export.xlsx "http://localhost:8000/api/v1/export?mode=full¢ers=01" \
  -H "Authorization: Bearer $TOKEN"

常见问题排查

现象排查
登录提示「网络错误」后端是否启动？curl :8000/health；代理是否生效？curl :5173/api/v1/auth/me
「用户名/密码/中心不正确」账号、密码、中心三者是否匹配（见测试账号）
401 后跳回登录页token 失效，属正常；用正确账号重新登录
列表为空但库里有数据医生只能看本中心；换对应中心账号登录
导出「无导出权限」需 admin 或 center_id=01 账号
访视/不良事件刷新后消失属分层边界，数据仍在前端 localStorage
