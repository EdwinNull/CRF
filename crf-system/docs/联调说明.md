# CRF 系统前后端联调说明

> 本文档供开发/测试人员手动验证前后端联调效果。最后更新：2026-08-11。

## 1. 系统架构

```
浏览器 (http://localhost:5173)
    │  axios, baseURL=/api/v1
    ▼
Vite Dev Server (:5173)  ── proxy /api ──▶  FastAPI (:8000)
                                                     │
                                              PostgreSQL (crf_db)
```

- **前端**：React 19 + Vite 8 + AntD 6，`src/api/` 为 API 封装层
- **后端**：FastAPI 0.109 + SQLAlchemy 2 + Alembic + PostgreSQL
- **代理**：Vite `vite.config.ts` 将 `/api` 请求转发到 `http://localhost:8000`，避免跨域

## 2. 启动服务

### 后端（端口 8000）
```bash
cd crf-backend
# 首次需先完成数据库迁移（已做过可跳过）
/opt/anaconda3/envs/crf/bin/python -m alembic upgrade head
# 启动
/opt/anaconda3/envs/crf/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 前端（端口 5173）
```bash
cd crf-system
npm run dev
```

两个服务都启动后，打开 **http://localhost:5173**。

校验：
- 后端健康检查 `curl http://localhost:8000/health` → `{"status":"ok"}`
- 前端 `curl http://localhost:5173/` → 200

## 4. 已接入后端的功能（联调范围）

| 功能 | 前端页面 | 后端接口 | 说明 |
|---|---|---|---|
| 登录 | 登录页 | `POST /auth/login` | 验证用户名/密码/中心；失败拒绝进入 |
| 患者列表 | 患者列表页 | `GET /patients` | 按角色隔离：医生仅本中心，admin 全中心 |
| 新建患者 | 患者列表页「新建患者」 | `POST /patients` | 后端建档 + 自动建 V1 空访视；center 自动取当前用户 |
| 患者详情 | 患者详情页 | `GET /patients/{id}` | 后端病案基础字段 |
| V1 筛选判定 | V1 访视页「提交」 | `PATCH /visits/V1` | 提交时后端判定入选/排除 → 患者自动 upgrade 为 treatment + 生成随机号 |
| 数据导出 | 导出页 | `GET /export` | admin / 中心01 可导出完整 Excel |

## 5. 仍为前端本地（分层边界）

以下仍由前端 `PatientContext` + localStorage 管理，**未**落库到后端：

- V1 详表（人口学、病史、四诊、实验室等富字段）
- V2–V6 访视明细（VAS/四分法/RQLQ/中医证候/药物评分等）
- 不良事件、合并用药、非药物疗法、完成情况

**原因**：后端将这些访视数据存为无结构 JSON blob，与前端强类型富模型差异大；强行落库会丢字段。界面显示、编辑均正常，只是刷新后不持久化到后端（仍走 localStorage）。

## 6. 手动联调验证清单

按顺序在浏览器操作：

| # | 步骤 | 预期 |
|---|---|---|
| 1 | 用 `doctor01`/`Doctor@0101` 登录（中心选 01） | 登录成功，进入患者列表 |
| 2 | 错误密码登录 | 提示"用户名、密码或研究中心不正确" |
| 3 | 患者列表新建患者，填筛选号 001、缩写 e.g. `AAAB`、入组日期 | 创建成功并跳转 V1；列表出现该患者（中心 01） |
| 4 | 用 `doctor02` 登录，看列表 | **看不到** doctor01 建的 01001 号患者（中心隔离生效） |

| 6 | 用 `doctor02` 进导出页 | 提示无导出权限（仅 center01/admin） |
| 7 | V1 页填写后提交（入选全选是、排除全否） | 患者状态从「筛选中」变「治疗中」，随机号自动生成 |

### 也可用 curl 直接验后端（绕过前端）
```bash
# 登录取 token
TOKEN=$(curl -s -X POST http://localhost:8000/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin@crf2026","center_id":"01"}' \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['access_token'])")

# 列患者
curl -s http://localhost:8000/api/v1/patients -H "Authorization: Bearer $TOKEN"

# 建患者
curl -s -X POST http://localhost:8000/api/v1/patients \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"screening_no":"01008","name_abbr":"BBBB","gender":"男","age":40,"height":170,"weight":65,"enrollment_date":"2026-08-11"}'

# 导出
curl -s -o export.xlsx "http://localhost:8000/api/v1/export?mode=full&centers=01" \
  -H "Authorization: Bearer $TOKEN"
```

## 7. 常见问题排查

| 现象 | 排查 |
|---|---|
| 登录提示"网络错误" | 后端是否启动？`curl :8000/health`。前端代理是否生效？`curl :5173/api/v1/auth/me` |
| 登录提示"用户名/密码/中心不正确" | 账号密码与中心是否匹配（见 §3） |
| 401 后跳回登录页 | token 失效，正常；用正确账号重新登录 |
| 患者列表为空但后端有数据 | 医生账号只能看本中心；确认用了对应中心账号登录 |
| 导出报"无导出权限" | 需 `admin` 或 `center_id=01` 的账号 |
| 访视/不良事件刷新后消失 | 属分层边界（§5），这些数据仍在前端 localStorage |
